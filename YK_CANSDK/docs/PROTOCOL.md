# 协议实现说明

## 网络侧固定帧

CAN115 配置为“标准协议转换”后，每个经典 CAN 帧在 TCP 字节流中固定占 13 字节：

```text
+0          +1..+4         +5..+12
帧信息 1B   CAN ID 4B      CAN 数据区 8B
```

帧信息：bit7 为扩展帧，bit6 为远程帧，bit5..4 必须为 0，bit3..0 为 DLC。运康控制和反馈均为扩展数据帧，所以 DLC=8 时首字节为 `0x88`。即使 DLC 小于 8，网络记录仍固定 13 字节，数据区补零。

TCP 没有“消息边界”。一次 `recv()` 可能得到半帧、正好一帧或多帧；SDK 的 `CanStreamParser` 维护缓存并验证候选帧，不能把一次 `recv()` 当一条 CAN 帧。

## 运康 CAN ID

29 位扩展 ID 的 4 字节表示为：

```text
0D EE DD FF
      │  └─ 功能码
      └──── 驱动器 ID（1..100，FF 为广播）
```

本车采用：

- `0x0DEE0100`：前轴驱动器 1 运行控制；
- `0x0DEE0200`：后轴驱动器 2 运行控制；
- `0x0DEE0101..04`、`0x0DEE0201..04`：速度、电气量、温度故障、位置反馈；
- `0x0DEE010A` / `0x0DEE020A`：V1.221+ 参数写入；
- `0x0DEE010B` / `0x0DEE020B`：参数写入返回。

## 运行控制数据

功能码 `0x00` 的 8 字节数据由两个有符号 int32 大端数组成：

```text
motor1[4] + motor2[4]
```

手册规定：开环 `-1100..1100`；速度闭环按电机额定转速；位置闭环按霍尔计数。SDK 的高级车辆层按开环模式设界，默认限制为 `±300`。若驱动器并非开环模式，不要直接沿用此默认值，应先核对寄存器 `0x0010`、`0x0011` 和电机参数。

调试工作簿给出的实车正向向量为：

```text
逻辑 M1=+100, 逻辑 M2=+100
原始 M1=+100, 原始 M2=-100
88 0D EE 01 00 00 00 00 64 FF FF FF 9C
```

因此方向取反属于车辆映射，不属于 CAN 协议本身。

## 通信保活和上电顺序

- 驱动器每次上电需要 10 条零速控制指令解除保护。
- 正确收到通信命令后驱动器循环返回数据。
- 500 ms 内没有正确命令时，驱动器停止返回并停止电机（位置闭环行为按手册说明）。
- SDK 默认 20 ms 刷新，软件目标 250 ms 未刷新即自动归零。

## 返回解释

| 功能码 | 数据区 | SDK 类型 |
|---:|---|---|
| `01` | int32 M1 + int32 M2 | `SpeedFeedback` |
| `02` | int16 电流1 + int16 电流2 + int16 电压 + 2B 固件字段 | `ElectricalFeedback` |
| `03` | int16 温度1 + int16 温度2 + uint16 故障1 + uint16 故障2 | `ThermalFaultFeedback` |
| `04` | int32 位置1 + int32 位置2 | `PositionFeedback` |
| `0B` | 0x83 + uint16 寄存器 + 保留 + uint16 值 + 保留 | `ParameterAck` |

功能码 `02`、`03` 的电流、电压、温度分辨率按说明书为 0.1。功能码 `02` 最后两字节在不同表述中出现“保留”与“前后/左右通道”的差异，SDK 不猜测，保留原始 `tail`。
