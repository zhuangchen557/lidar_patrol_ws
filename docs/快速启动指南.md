# 巡检车开发环境 — 快速启动指南

## 推荐：一键启动

### 前置（重启电脑后必做）
CAN115 通过**主板网口**（Realtek）连接，重启后静态 IP 会丢，需管理员运行：
```
docs/fix_can115.bat     # 自动设 192.168.0.100/24 并验证 CAN115
```
> 注：原 ASIX USB 网卡已损坏（无法识别），现用网线直插主板网口。

### 启动步骤
**1. 管理员 PowerShell 挂载雷达 USB：**
```powershell
usbipd list    # 找 USB-SERIAL CH340，记下当前 BUSID（重启后 busid 可能变）
usbipd attach --wsl Ubuntu --busid <busid>
```

**2. 双击运行 `docs/start_car.bat`（只开一个！）**
自动完成：清理旧转发器 → 起 TCP 转发器 → 挂载雷达 → 编译 → 启动 bringup
（bringup 含：底盘 + 雷达 + TF + scan_repub + rosbridge，全链路一键起）

> ⚠️ **bat 注意**：
> - **不要同时开两个 bat**，两个 colcon 会抢 build 锁卡死编译
> - 若报 `'powershell' is not recognized`：改用完整路径 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`
> - 转发器会随 bat 窗口关闭被杀，被杀后底盘进模拟模式，需重启底盘节点（见排查表）

## 手动分步启动（排错用）

### 0. 检查 CAN115 网卡 IP（重启后必查！）
```powershell
# 管理员运行 docs/fix_can115.bat，或手动：
$idx = (Get-NetAdapter | Where-Object { $_.InterfaceDescription -like "Realtek*" -and $_.Status -eq "Up" }).ifIndex
netsh interface ip set address name=$idx static 192.168.0.100 255.255.255.0
# 验证：python -c "import socket;print(socket.create_connection(('192.168.0.7',5578),3))"
```

### 1. 起底盘转发器（Windows，注意保活）
```powershell
python "E:\...\23生产实习\docs\forward_5578.py"
```
> **保活**（关窗口不死的常驻方式）：
> ```powershell
> Start-Process -WindowStyle Hidden -FilePath "python" -ArgumentList "E:\...\docs\forward_5578.py"
> ```
> 确认：`netstat -ano | findstr 5578` 有 LISTENING。
> 单客户端模式：新连接自动断开旧连接，重复启动无害。

### 2. 挂载激光雷达（管理员 PowerShell）
```powershell
usbipd list    # 找 CH340 的当前 busid（不固定！）
usbipd attach --wsl Ubuntu --busid <busid>
```

### 3. 加载雷达串口驱动（WSL 里）
```bash
sudo modprobe ch341
sudo chmod 666 /dev/ttyUSB0
ls /dev/ttyUSB0
```

### 4. 启动整车（WSL 里，含底盘+雷达+TF+repub+rosbridge）
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
ros2 launch vehicle_bringup bringup.launch.py
# 预期：已连接 CAN115(127.0.0.1:5578) + 雷达 normal + TF + rosbridge(9090)
```

## 日常使用命令

### 键盘遥控（新终端）
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
# 按键: i=前进  ,=后退  j=左转  l=右转  k=停（tune 已标定，turn 1.0 可正常转）
```

### 查看话题 / 里程计 / 雷达
```bash
ros2 topic list
ros2 topic echo /odom --once
ros2 topic echo /scan --once     # 360° 点云
```

### 障碍物扫描分析（新增）
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
python3 scripts/scan_analyze.py
# 输出：前方±45°/±90°、左右 30° 扇区、后方的最近障碍物距离与角度
```

### Rviz2 可视化（WSL 里）
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
rviz2
# Fixed Frame → base_laser → Add → /scan (LaserScan) + TF + /odom
```
> 需要 WSLg（Windows 11 自带），窗口自动弹到桌面。

### 落地旋转标定（已标定：MAX_ANGULAR_SPEED=1.67，重标定用）
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
ros2 run vehicle_bringup chassis_node        # 只起底盘
python3 scripts/recalibrate_rot.py           # 满速转 4 秒数圈
python3 scripts/recalibrate_rot.py --speed 2.0 --duration 5   # 慢速标定
```
> 实测结论（2026-08-27）：满速实际 1.26 rad/s；**15% 出力有死区转不动，需 ≥30% 出力**；
> 故 MAX_ANGULAR_SPEED=1.67（0.5 rad/s 命令 = 30% 出力）。改完 `colcon build --packages-select vehicle_bringup` 重启底盘。

### 避障测试
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
ros2 run lidar_avoidance laser_avoidance    # 或 launch avoidance_test.launch.py
```
> **避障逻辑**（已标定+侧向独立参数）：
> - 前方 <stop(0.5m) 或侧向 <side_stop(**0.30m**) → TURN 停+转向空旷侧
> - 前方 <safe(1.0m) 或侧向 <side_safe(**0.30m**) → SLOW 减速
> - 参数在 `src/lidar_avoidance/config/avoidance.yaml`（前方/侧向距离独立配置）
> ⚠️ 不要和 waypoint_player 同时跑，会抢 /cmd_vel

### 路线录制 / 回放
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
# 录制（注意: 参数必须用 --ros-args -p，裸 key:=value 会被当 remap 导致 map TF 报错）
ros2 run navigation waypoint_recorder --ros-args -p output_file:=src/navigation/routes/patrol_route.json -p map_frame:=odom
# 另开终端键盘遥控走一遍，走完在录制器终端 Ctrl+C 保存
# 回放（直控模式，回放前车需在录制起点附近）
ros2 run navigation waypoint_player src/navigation/routes/patrol_route.json --ros-args -p use_nav2:=false -p dwell_seconds:=2
```

### Nav2 自主导航（使用庄晨地图 my_map.pgm）
```bash
cd ~/lidar_patrol_ws && source install/setup.bash
ros2 launch vehicle_bringup bringup.launch.py use_nav2:=true
# 另开终端 RViz：rviz2 -d config/nav2.rviz（已配置地图/点云/粒子/位姿显示）
```
- 定位：RViz 工具栏 **2D Pose Estimate** 点车实际位置（或 `ros2 topic pub -1 /initialpose ...`）
- 导航：**2D Goal Pose** 点目标，或 `ros2 action send_goal /navigate_to_pose ...`
- **footprint 碰撞半径 0.30m**（2026-08-28 实车调整，nav2_params.yaml，便于窄道通行）
- 前置：场地需与 my_map.pgm 对应；车周围 1m 清空（costmap 障碍层会占据起点导致规划失败）
- 调试话题：`/amcl_pose`(定位) `/particle_cloud`(粒子) `/cmd_vel`(速度指令)

### EnzoPatrolLab 实验台（Windows）
```
双击 Enzo巡迹实验台.exe
```
> **已改造为 rosbridge 版网关**（雷达双端方案）：
> - 雷达数据：WSL `/scan` → scan_repub(RELIABLE) → rosbridge → gateway-ros2 → 前端雷达图
> - 温湿度：Windows 直读 COM3（LES11B，experiment-config 已写死 COM3）

> - 详细见 `web/robot-monitor/gateway-ros2/README.md`

## 已知问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| chassis_node 报 Connection refused 进模拟模式 | 转发器没起 | 起转发器（见步骤 1），**重启底盘节点**（模拟模式不会自动重连） |
| bat 卡在"编译最新代码" | 同时开了两个 bat，colcon 抢锁 | 只开一个；已卡死则任务管理器杀 python 后重跑 |
| CAN115 不可达 | 重启后主板网口 IP 丢失（169.254.x.x） | 管理员跑 `fix_can115.bat` |
| 雷达 /dev/ttyUSB0 不存在 | USB 没重挂或 busid 变了 | `usbipd list` 找 busid → attach → modprobe ch341 + chmod 666 |
| 雷达进程活着但 /scan 无数据（首次初始化卡死） | LD19 节点 usbipd 下偶发卡死 | 杀掉重启雷达节点：`ros2 launch ldlidar ld19.launch.py` |
| EnzoPatrolLab 显示"等待 rosbridge /scan 数据" | rosbridge 启动时 /scan 尚未广告，订阅失败 | 重启 rosbridge 会话 + 重启实验台（bringup 已保证顺序，重启后一般不再犯） |
| 避障侧向老触发 TURN | 侧向距离用了前方 stop(0.5m) | 已改独立参数 0.30m（side_stop_distance/side_safe_distance） |
| 地面转弯无力 | MAX_ANGULAR_SPEED 未标定 | 已标定 1.67；重标定见上文 |
| 避障只往左转、右边永远 inf | 旧版 sector_min 角度过滤 bug | 已修复（809f328），更新代码即可 |
| Ctrl+C 退出报 context 失效 | 已知修复（59cc646 同类） | 已修复，无需处理 |
