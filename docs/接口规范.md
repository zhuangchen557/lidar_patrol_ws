# ROS2 接口规范

> **！！！重要提醒：所有人写代码时必须严格按照本文档中的 Topic 名称、消息字段名、坐标系名称来命名。任何一处不一致都会导致联调失败，到时候排查非常浪费时间。**

---

## 一、Topic 列表

| Topic | 消息类型 | 发布者 | 订阅者 | 说明 |
|-------|----------|--------|--------|------|
| `/cmd_vel` | `geometry_msgs/Twist` | 键盘节点 / waypoint脚本 | 底盘节点 | 小车的线速度和角速度命令 |
| `/odom` | `nav_msgs/Odometry` | 底盘节点 | SLAM / Nav2 / 可视化 | 里程计（小车位置和速度估算） |
| `/scan` | `sensor_msgs/LaserScan` | 激光雷达节点 | SLAM / Nav2 | 激光雷达360°扫描数据 |
| `/sensor/temp_hum` | `custom_interfaces/SensorData` | 温湿度节点 | 可视化 / 存储 | 温度(℃) + 湿度(%) |
| `/sensor/noise` | `custom_interfaces/SensorData` | 噪声节点 | 可视化 / 存储 | 噪声(dB) |
| `/map` | `nav_msgs/OccupancyGrid` | SLAM Toolbox | Nav2 / 可视化 | 2D栅格地图 |

> **注意：**
> - `/sensor/temp_hum` 和 `/sensor/noise` 是两个独立 Topic，分别发布，不要合并成一个。
> - 温湿度节点只发温度+湿度，噪声节点只发噪声分贝，互不干扰。
> - 发布者用 `custom_interfaces/SensorData` 发送时，不用的字段填 `0.0` 即可（如噪声节点只填 `noise_db`，其余字段填0）。

## 二、自定义消息格式

### SensorData.msg

```
float32 temperature           # 温度，单位：摄氏度（℃）
float32 humidity              # 湿度，单位：百分比（%）
float32 noise_db              # 噪声，单位：分贝（dB）
builtin_interfaces/Time timestamp  # 采集时间戳
```

> **注意：**
> - 这个 `.msg` 文件定义在 `src/custom_interfaces/msg/SensorData.msg`，是共享消息。
> - 如果修改此文件（增删字段），必须 `colcon build` 重新编译，并通知**全部组员重新编译**，否则其他人代码会因消息版本不一致而报错。
> - `timestamp` 字段用数据采集那一刻的时间，不要用发送时刻的时间。

### Waypoint.msg

```
float32 x                     # 巡检点X坐标（相对map坐标系，单位：米）
float32 y                     # 巡检点Y坐标
float32 yaw                   # 朝向角（单位：弧度，不是角度）
string label                  # 巡检点名称，如 "工位A"
```

> **注意：**
> - `yaw` 是弧度（rad），不是角度（°）。录制的 odom 数据中朝向角本身就是弧度，直接存即可，不要做转换。
> - `x` 和 `y` 是相对 `map` 坐标系的值，录制时小车必须在 SLAM 建图完成后进行。

## 三、TF 坐标系

| TF链接 | 父坐标系 | 子坐标系 | 发布者 | 说明 |
|--------|----------|----------|--------|------|
| `map → odom` | map | odom | SLAM / AMCL | 纠正里程计累积误差 |
| `odom → base_link` | odom | base_link | 底盘节点 | 里程计到车体中心 |
| `base_link → laser` | base_link | laser | 静态TF | 车体中心到激光雷达安装位 |

### 坐标系层级

```
      map（世界坐标系，SLAM建图产生）
       ↑
       │ AMCL发布（map→odom）
      odom（里程计坐标系）
       ↑
       │ 底盘节点发布（odom→base_link）
   base_link（车体中心）
       ↑
       │ 静态TF（base_link→laser，雷达的实际安装偏移量）
    laser（激光雷达坐标系）
```

> **注意：**
> - 三个 TF 缺任何一个，Nav2 都无法正常工作。
> - `base_link → laser` 是静态 TF，雷达固定后测量它在车体上的实际位置（x,y,z 偏移量）填入 launch 文件即可，建图后再测量一遍核对。
> - TF 发布频率至少 30Hz（`/odom` 用该频率发布），频率太低会导致定位跳跃。
> - 各帧的 `frame_id` 和 `child_frame_id` 必须与上表完全一致，大小写也要一致。

## 四、Nav2 行为定义

| Action | 说明 | 调用者 |
|--------|------|--------|
| `/navigate_to_pose` | 导航到单个目标点 | waypoint回放脚本 |

> **注意：**
> - waypoint回放脚本调用此 Action 时，目标点的 `frame_id` 必须设为 `"map"`，否则 Nav2 不知道目标点在哪个坐标系下，会直接报错 reject。

## 五、联调前自检清单

在参加组内联调之前，每人先确认以下项：

| 检查项 | 验证方法 |
|--------|----------|
| 发布的 Topic 名称与本文档一致 | `ros2 topic list` 列出所有话题，逐条对比 |
| 发布的消息字段名与本文档一致 | `ros2 topic echo <话题名> --once` 查看字段名 |
| TF 树完整且无断裂 | `ros2 run tf2_tools view_frames` 生成 PDF 查看 |
| 自定义消息编译通过 | `ros2 interface show custom_interfaces/msg/SensorData` 能显示字段 |
| 发布频率满足要求（odom ≥ 30Hz, sensor ≥ 1Hz） | `ros2 topic hz <话题名>` |
